UI migration · crowsnest

From hand-rolled markup to shadcn compositions

A composition-level migration of the whole product surface: panels, forms, rows, tables, empties, the app shell and every chart now come from the vendored shadcn primitive set instead of being rebuilt by hand in each feature directory.

7 commits 117 product files +6,439 / −5,228 11 phases 14 routes verified
The ask that started it “Plan hiện tại chưa oke đâu. NÓ chưa thật sự là ‘migrate UI’.” — the previous plan swapped elements (<button> → Button) and deferred every composition. This one replaces the layer above the element.
TL;DR

The repo already vendored all 62 shadcn base-maia primitives, but the product tree never used them above the element level. Every panel was a hand-rolled div.border.border-border.bg-card, every form row a hand-stacked label plus input, every list row a flex items-center justify-between, every empty state a centered paragraph, and four grids pretended to be tables. Nine primitives had zero consumers outside the /gallery demo.

That layer is gone. Card went from 4 importers to 52, Table from 3 to 16, and Field, Item, Empty, ButtonGroup, InputGroup, Spinner, Chart, Kbd and Sidebar went from zero to real use. The 486-line hand-written sidebar is now the shadcn Sidebar block, the app works at 375px, and seven hand-drawn SVG charts are Recharts.

New behaviour the block brought
The rail's collapsed width now survives a reload: the shell layout reads the sidebar_state cookie server-side, so the page paints collapsed instead of mounting expanded and snapping shut. ⌘B toggles it. Below 768px the rail leaves the layout entirely and the topbar trigger opens it as a sheet.
One correction worth recording
Mid-verification the unsaved-changes guard looked broken, and it was briefly rewritten as a capture-phase handler. It was not broken — the test was lying. The dirty-state probe matched a “Save changes” button that renders disabled when the board is clean, so the board was never actually dirty. With a real dnd-kit drag, onNavigate works fine through both Base UI useRender merges. The rewrite was reverted; only an explanatory comment remains.

Two things deliberately not handed to the library

The log scales stay ours. viewScalePosition and scalePosition are tested pure functions that three screens read. Letting Recharts derive its own scale="log" would give one screen a silently different definition of the same axis, so both axes plot a 0..1 position and label the ticks by hand.

sparkline.tsx stays hand-drawn. It is a 64×20px trend mark inside a table cell; ResponsiveContainer would measure-loop there. Wrong tool.

dashboard-chart-data.ts is byte-unchanged and its tests pass untouched, so every caption number is identical by construction. Verified on screen: the donut legend sums to the 176 posts its caption claims, and the scatter's 337 plotted plus 839 omitted equals the 1,176 synced the same page reports.

5. Type scale and tokens

The app overrode Tailwind's whole type scale. That is fine when every component is hand-written, and wrong the moment the primitives arrive: CardTitle is authored as text-base and CardDescription, FieldDescription and Item as text-sm, so an inflated scale inflates every composition. The override is gone.

  • Deleted --text-xs through --text-xl. Kept --text-2xs, the one step Tailwind has no equivalent for, now 11px across its 282 call sites.
  • Deleted the global button:not(:disabled):active { filter: brightness(0.9) }. An element selector that fired on every Base UI trigger and stacked a second dimming pass on top of ui/button.tsx's own pressed treatment.
  • Dropped two dead next/font imports (Archivo, Geist) and the comment that still claimed Archivo carried the words.
  • The --sidebar-* token family was defined in globals.css and used by nothing. The Sidebar block uses it now.

9. Deliberately left alone

A migration is judged as much by what it refuses to touch. Each of these was considered and rejected with a reason recorded in the code.

WhatWhy it stays
src/app/global-error.tsxRenders its own <html> outside the root layout, so globals.css never loads there. Its inline styles are correct; Tailwind classes would not apply. The previous plan wrongly listed it for migration.
dashboard/sparkline.tsxA 64×20px inline trend mark. ResponsiveContainer would measure-loop inside a table cell.
layout/command-menu.tsxAlready a real CommandDialog.
app/(shell)/(loaded)/channels/page.tsxA full-height flex shell with a sticky footer around the kanban. PageContainer's gutter is exactly what would break it; the padding went inside the kanban instead.
Drag handles, day cells, video thumbnailsClickable surfaces that are a whole card or cell, not a button. Forcing Button on them would be wrong.
Two cn import sourcessrc/components/ui/* imports the npm cn; app code imports @/lib/utils. Unifying them would diverge the vendored files from what shadcn add writes.
Inline “no items yet” linesA single muted line inside a list or a log stays one line. Empty is for a whole view or a whole panel.
Legend swatchesTwo 12×12px border border-border bg-card squares in the calendars. No primitive is a coloured square.
