# Crowsnest QA pass (functional)

Report-only browser pass against `main` / `8909788`, dev server at http://localhost:3000.
Nothing was fixed, no code changed, no commits, no branch switches. HEAD did not move
during the pass.

Method: gstack browse (headed Chromium) driving the real app. Screenshots under
`.gstack/browse-cwd/qa/`. A few findings were confirmed with read-only `sqlite3` queries
against `data/crowsnest.db` to tell a UI bug apart from a data-coverage fact.

Status: partial, in two stretches. The second stretch ended when another reviewer took the
shared browser (the URL moved between polls without my input and the theme switched to
dark), so browser work stopped there rather than contend for it. See "Not tested" at the
end.

## What works

Worth stating plainly, because most of the app held up.

- Console is clean. Zero JS errors across dashboard, feed, video detail, channels,
  channel detail, runs, run detail, logs, vault (4 tabs), my channel, settings, remix.
  The only console output anywhere was a Chromium notification-permission warning, which
  comes from the browser profile, not the app.
- Frame pass works end to end. On `/feed/a0ed7179-.../` (Hook & structure tab) the button
  read "Re-run frame pass", the click inserted a `frame_pass_jobs` row with
  `status = 'running'`, the button became a disabled "Running…" chip, the previous reading
  stayed on screen while the pass ran, and about 40 seconds later the section re-rendered
  with a fresh reading and the button returned to "Re-run frame pass". Job row went to
  `success`, 58 frames sampled, `claude-code/watch+sonnet`.
- The global one-pass-at-a-time lock holds, and it tells the user. With a pass running on
  video A, clicking "Re-run frame pass" on video B created no second job row and raised a
  toast: "A frame pass is already running. Passes run one at a time."
- View count enrichment landed. Real numbers render on the feed cards, the dashboard tiles
  and the channel pages: @kallaway 25M, @mavgpt 3.1M, @jun_yuh 1.4M, @nick_saraev 1.97M.
  Outlier scores compute off them.
- The frame pass "never run" state is well built. On the one video that has an analysis but
  no downloaded file, the Layout section renders all four fields as dashes and explains
  itself: "No frame pass has run for this video yet. Running one samples frames and reads
  on-screen text, its position, cut rhythm, and framing from them. Nothing above is a guess
  standing in for a reading." That last sentence is the anti-fabrication invariant made
  visible to the user, and the dashes honour the never-a-fabricated-zero contract.
- The no-video-asset path fails correctly. Clicking "Run frame pass" on that video wrote a
  job row with `status = 'failed'`, `error_code = 'FRAME_NO_VIDEO_ASSET'`, message "video
  has no downloaded video asset (sync with downloads first)". The page also carries a
  "Download video" button, so the recovery the message asks for is at hand, which is better
  than the surface map's usability note anticipated.
- Blocked and empty states read well. `/mine` with no Graph token names the two env vars,
  says what connecting would add, and still renders the planner. The Vault empty state
  explains why saving a post is useful instead of just saying "nothing here".
- The dashboard dependency panel called the LLM problem before I found it, and told the
  user how to confirm it ("Try one in Remix to know for sure"). That prediction turned out
  to be exactly right, see H1.

## Findings

### H1 (high) Remix script generation fails against the LLM proxy

Screen: `/feed/<videoId>/remix`, stage 5 (Script).

Steps:
1. Open `/feed/a0ed7179-1b66-4f2e-90c9-03e81429f9fc/remix`. A prior session restores at
   stage 5 with 3 variants already generated.
2. Click "Regenerate" on Variant 1.
3. Click "Retry" when it fails.

Expected: a new script variant, the way the 3 stored ones were produced 3 days ago.

Actual: fails in about 1.4 seconds, both times. The panel shows "Couldn't generate this
variant / request ended without sending any chunks" with a Retry button. The run log
records "Script, variant 1 failed: request ended without sending any chunks, Failed 1.4s".

The proxy is up and answering. `curl http://localhost:20128/v1/models` returns the model
list (openclaw, hermes, nvidia/minimaxai/minimax-m2.7, and others). So the failure is in
the streaming path, not connectivity, which matches the dashboard's own reading that a
token-count check is not proof of generation.

Ranked high rather than blocker because it looks like the 9router proxy relaying nothing
on the stream rather than app code, and because the app handles it well: named error,
Retry button, run log entry, no crash. It does mean Flow E is unusable right now.

### H2 (high) A sync run's log events are not tagged with its run id, so the run trace is nearly empty

Screen: `/runs/<runId>`, the Trace panel.

Steps:
1. Open `/runs`, click View on the most recent "Library sync" (14:41, 10 of 10 channels,
   31 new, 386 updated).
2. Read the Trace panel, which is labelled "log events for run_id ...".

Expected: the run's log events, enough to explain the counters above it.

Actual: 3 lines. `sync.started`, `sync.started.detached`, `sync.finished`.

That run emitted 1,689 log events. Only those 3 carry a `run_id`; every other event has
`run_id` NULL, including the ones a reader would want:

| event | count in window | untagged |
| --- | --- | --- |
| download.completed | 777 | 777 |
| asset.deduped | 716 | 716 |
| asset.stored | 61 | 61 |
| medias.page | 42 | 42 |
| sync.channel.started | 10 | 10 |
| sync.channel.finished | 10 | 10 |
| sync.enrich.finished | 10 | 10 |
| sync.soft_deleted | 1 | 1 |
| sync.item.failed | 1 | 1 |

The sharp end: the run header shows "Failed 1", and the single `sync.item.failed` event
that would say what failed is untagged, so it never appears in that run's trace. A user
who sees the failure counter has no path from it to the reason. This is the "Runs and Logs
as a debugging pair" case in the surface map, and today the pair is broken.

Also affects the new enrichment feature specifically: `sync.enrich.finished` fires 10 times
per library sync and none of them show up on the run that caused them.

### H3 (high) The frame pass button only exists on a video that has already been analysed

Screen: `/feed/<videoId>`, Hook & structure tab.

Steps:
1. Open `/feed/0b033d3d-c84d-4c62-8b44-01b2d15650c2`, a video with no analysis row. Click
   the Hook & structure tab. The buttons present are Transcribe & Analyze, Keep this post,
   Save to Vault, Copy as prompt. There is no Layout section and no frame pass button.
2. Open `/feed/a68a0361-f429-4091-a66f-e83096ab7ed2`, which has an analysis row but no
   downloaded file. Same tab. The Layout section renders and "Run frame pass" is there.

The only difference between the two is the `video_analyses` row, so the Layout section is
gated on an analysis existing.

Why it matters: 9 of 449 live videos have an analysis row. The frame pass shipped this
session and its only entry point is present on 2% of the library. To reach it on any other
video the user has to run Transcribe & Analyze first, and nothing anywhere says so. The
feature reads as missing rather than as gated, which is how I first recorded it before
finding the fixture that proved otherwise.

The gate itself may well be deliberate, since a layout-only analysis row is legal per the
surface map and the section has to hang off something. The problem is that it is silent.

Confidence: the positive case is solid (two videos differing only in that column, opposite
outcomes). The negative case is one video, because the browser became unavailable before I
could repeat it on a second unanalysed video. Worth a second look before acting.

### M1 (medium) A library sync now overruns its own budget, and the run still reads plain Success

Screen: `/runs/<runId>` header.

Steps: open the most recent Library sync run.

Expected: either the run finishes inside its budget, or the overrun is visible.

Actual: "Elapsed 14:41" against "Budget 10:00", status "Success", no breach indicator in
the header.

This is the cost of the enrichment pass showing up. Enrichment is the longest stretch of
authenticated requests in a run and it sits before scoring. A budget that the normal path
now exceeds by 47% is a budget that no longer means anything, and it interacts with the
stall and stale-lock thresholds the surface map flags (`SYNC_STALL_SECONDS`, `LOCK_STALE_MS`).
Either the budget moves or the overrun gets surfaced.

### M2 (medium) Most tracked posts still have no view count, and the feed does not say so

Screen: `/feed`, `/` dashboard.

Steps: open `/feed`, read "452 results". Open `/`, read the scatter and ranking captions.

Actual: the dashboard is honest about it ("113 posts plotted, 339 left out for missing a
score or a view count", "113 scored, 339 not scored yet"). The feed is not: it says "452
results" and sorts by "Highest score" with no indication that 339 of those 452 cannot be
scored at all.

Coverage per channel, posts with a null or zero view count:

| channel | posts | no view count |
| --- | --- | --- |
| @danmartell | 120 | 105 |
| @jun_yuh | 57 | 45 |
| @mavgpt | 49 | 35 |
| @personalbrandlaunch | 60 | 48 |
| @hormozi | 60 | 48 |
| @chase.h.ai | 32 | 20 |
| @nateherkai | 30 | 18 |
| @nick_saraev | 23 | 11 |
| @kaiships.ai | 9 | 7 |
| @kallaway | 12 | 0 |

This is the enrichment knob working as designed (newest N reels per channel, and @kallaway
at 12 of 12 is simply a channel smaller than N). It is not a bug in the pass. It is a
reporting gap: sorting 452 results by score when 339 have no score is a ranking the user
cannot interpret, and the feed never mentions it the way the dashboard does.

### M3 (medium) The Vault header count does not follow the active tab

Screen: `/vault`, tabs Scripts / Hooks / Styles.

Steps:
1. Open `/vault?tab=scripts`. Seven scripts render.
2. Read the header.

Expected: a count that matches what is on screen, or a header that is clearly not about
this tab.

Actual: the header reads "0 saved posts" on every tab, including while 7 scripts are
listed below it.

The number itself is right (`saved_posts` really is 0, `vault_items` 2, `scripts` 7, and
the dashboard's "Vaulted this week 2" reconciles). It is the placement that misleads: it
sits where a page-level count goes and contradicts the visible contents on 3 of 4 tabs.

### M4 (medium) Frame pass is buried in a non-default tab

Screen: `/feed/<videoId>`.

Steps: open any video detail. The Transcript tab is selected by default. Look for the frame
pass.

Actual: the Layout section and its button live inside the "Hook & structure" tab. Nothing
on the default view hints that a Layout reading exists or can be run. I initially concluded
the feature had no UI at all, and only found it by dumping the other tabs.

The feature shipped this session and its only entry point is one click away from anything
that mentions it. Worth a pointer from the default tab, or surfacing Layout at page level.

Compounds with H3: the tab is the second gate, the analysis row is the first.

### L1 (low) The sidebar footer sync status is clipped by the avatar

Actual: the avatar circle overlaps the status text, which renders as "nced 24m ago" instead

### L2 (low) Scores below 0.05x render as "0.0x", which reads as missing data

Screen: `/channels/<channelId>` video grid, `/feed` cards.

Steps: open `/channels/<danmartell>`, look at the newest post (4.5K views, 55m ago, against
a 109.2K median).

Actual: "0.0x". The real value is about 0.04x. The stat tile contract in the surface map
says a dash should never be a fabricated zero; this is the mirror of that problem, a real
value rendered as a zero. Same shape on engagement: the detail page shows "0.0% engagement"
for the @kallaway post where the feed card for the same post shows "0.01% eng", so the two
surfaces disagree on precision as well.

### L3 (low) The outlier scale bar clamps at 12x while showing values far past it

Screen: `/feed/<videoId>`, the median baseline bar.

Steps: open the @kallaway post scoring 116.5x.

Actual: the bar is axis-labelled 0.2x, 1.0x = 215.1K, 12x, and the fill is pinned hard at
the right end. A 116.5x value on a 12x axis conveys nothing except "off the chart", and it
looks identical to a 12x post.

### L4 (low) Plural not handled on the channel card outlier count

Screen: `/channels`.

Actual: cards read "1outliers 30d" for @danmartell. Two problems in one string, the missing
space and the plural on a count of 1.

### L5 (low) "Only 2 posts" on a channel with 9 posts

Screen: `/channels`, the @kaiships.ai card.

Actual: "Only 2 posts, a median needs about 10 before its scores mean anything." The channel
has 9 posts. Two of them have usable view counts, which is what the sentence is really
about, so the number is correct and the noun is wrong. Reads as a data bug when it is a
coverage statement. Saying "only 2 posts with view counts" would be both true and clear.

### L6 (low) The already-running toast is hard to read

Screen: `/feed/<videoId>`, after clicking frame pass while another pass runs.

Actual: the toast renders bottom-right at low contrast, overlapping the Layout section text
underneath it. The message is the right message (see the What works section) but it competes
with the body copy it sits on top of.
