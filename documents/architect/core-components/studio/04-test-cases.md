# studio: test cases

How to run these: start from a planned post that has a saved script attached and a source video, opened in the studio at `/mine/{postId}/studio` (reach it from the remix finish stage or from the plan dialog's "Create in Studio" button). Most brief rows are a plain read and need only that plan on screen. The cook, publish, and save rows need a real cook session: opening the studio spawns one on its own, and the local `claude` binary plus the `ksa` plugin must be reachable for it to actually render. A run that fails or is stopped leaves no publishable render. For the reload rows, keep one cook running and reload the page while it is still working. Offline coverage runs with `vitest` against a temporary SQLite database: `queries/studio.test.ts`, `studio/write-brief.test.ts`, `studio/paths.test.ts`, and the whole `server/terminal/*.test.ts` suite (`ws.test.ts`, `cook-queue.test.ts`, `session-registry.test.ts`, `harness-profile.test.ts`, `session.test.ts`, `pty-perms.test.ts`, `render-watch.test.ts`), all with the pty and the filesystem faked, no real `claude` binary needed. Browse-e2e cases are driven with the `browse` skill against the running dev server, per `references/browse-e2e-qa.md`; none of the `data-testid` values the journey below needs exist in the current markup, so that case is blocked on adding them first.

## 4. security-lite

Studio has no license gate of its own and makes no outbound call the app controls; the only outbound reach from this component is Instagram's Graph API, and that is reached exclusively from inside the injected `/ksa:serve` agent session, never from app code. There is no separate secret the studio itself holds: the cook session authenticates to Claude Code through the same OAuth session the harness inherits, not an API key the app stores or could leak.

| ID | P | Threat | Claim | Setup | Steps | Expected | Result |
| --- | --- | --- | --- | --- | --- | --- | --- |
| SEC-01 | P2 | No buyer data leaving the box | The planned posts table has no code path to any network call; nothing the studio itself does, short of the agent session, can reach Instagram. | A planned post with a render captured. | 1. Click Save to calendar (not Publish) and inspect outbound network activity from the Next.js process. | No outbound call to Instagram or any other host is made by the app process itself; only the database is written. | not run |
| SEC-02 | P2 | Secret handling | The cook session's environment is scrubbed of credential-looking keys and every `CLAUDE_CODE_*` key before spawn, so the child cannot inherit this process's own session markers or secrets. | A running Next.js process with its own `CLAUDE_CODE_*` environment set. | 1. Spawn a cook session.<br>2. Inspect the child process's environment. | No `CLAUDE_CODE_*` key or credential-looking key from the parent process appears in the child's environment (`scrubbedTerminalEnv`). | not run |

Security-lite has no rows for the license gate or the sidecar shared token: the studio does not check a license itself, and it never calls the sidecar. The row that would normally cover a per-request auth token does not apply here; the only authenticated boundary the cook session crosses is Claude Code's own OAuth session, established once outside this component's own code.
