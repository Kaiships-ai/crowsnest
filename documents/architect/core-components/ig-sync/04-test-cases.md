# ig-sync: test cases

How to run these: the sidecar must be up. From the repo root, `npm run ig:service` starts it (the wrapper loads `.env.local` and execs the module); it binds `127.0.0.1:8765` only. `.env.local` needs `IG_SERVICE_TOKEN` (at least 16 chars, shared with Node) and, for anything past `/health`, a real `IG_USERNAME`/`IG_PASSWORD` for a burner account, never one you care about; the account can be challenged or banned. Do the first login with the `curl` sequence in `services/ig/README.md` (`/login`, then `/two-factor` or `/challenge/resolve` as asked). For the app side, start the dev server and open `http://localhost:3001` for the behavior and browse-e2e cases. Offline unit and integration tests run with `uv run pytest` in `services/ig/` (150+, no network) and `vitest` for the Node suite, covering `sync-engine` (including the worker pool and cursor resume), `sync-batch`, `ig/errors`, `ig/client`, `sync-actions`, and `queries/runs` against a temporary SQLite database. Cases marked `live` in the Needs column need a real Instagram account and cannot be exercised offline; they are the burner-holder's steps. Browse-e2e cases are driven with the `browse` skill against the running dev server, per `references/browse-e2e-qa.md`; the add-channel and channels-board `data-testid` values these journeys use now exist in `add-channel-dialog.tsx`, `kanban-board.tsx`, `channel-card.tsx`, and `sync-selection-bar.tsx`, and the one journey still blocked on a missing testid (the Settings backfill button, E2E-03) names it in its own Setup and is filed in GitHub issues (label `backlog`).

Result markers: 🟢 ran and passed, 🔴 ran and failed, 🟡 blocked on a dependency the sandbox lacks (named). A browser-run case that passed cites its screenshot under `test-shots/<component>/` (local, gitignored) as the evidence. `not run` means the case is written but its verification has not run yet.

## 3. browse-e2e

Coverage: one happy-path journey per built (`●`) feature in the `03` summary table, features 2, 3, 4, and 5 (feature 6, TikTok/YouTube Shorts, is `○` roadmap and exempt). - Any journey through the sync-in-progress UI (the progress panel, the failure strip) is not scripted here; those surfaces belong to their own components and are exercised through their own browse-e2e cases.
