# analyze: test cases

Result markers: 🟢 pass, 🔴 bug, 🟡 blocked (missing dependency named in the cell). Rows still reading "not run" were not driven in QA round 1.

How to run these: start the dev server and open `http://localhost:3001` (never `127.0.0.1`), on a database with at least one tracked channel that has finished a sync. Seed a mix: an unanalyzed video and an analyzed one, one video with a stored transcript and one without, one video with no downloaded video asset yet, and a way to toggle the transcript providers (whisper.cpp local, or a Groq key) and the Claude API key. The behavior rows need a transcript provider and the Claude key for the analyze cases, and the LLM proxy up and a key for the idea rows. Stop the LLM proxy (or unset `LLM_BASE_URL`) for the proxy-down state, and unset `ANTHROPIC_API_KEY` for the no-key state, the two read differently. "A second tab" shares the session; it is not a second browser. The route and action lens runs offline with `vitest` against a temporary SQLite database, no external service needed, covering `analyze.ts`, `analyze-actions.ts`, `ideas.ts`, and `auto-analyze.ts`; every listed test already exists in the matching `*.test.ts` file. Browse-e2e cases are driven with the `browse` skill against the running dev server, per `references/browse-e2e-qa.md`; none of the `data-testid` values these journeys need exist in the current markup yet (filed as B-19), so every browse-e2e case is blocked on adding them first. The offline rows run against the seeded fixture database with no external service; the live rows need a reachable Claude proxy and a key.

## 3. browse-e2e

Coverage: one happy-path journey per built feature (`#2` analyze and reanalyze, `#3` generate an idea), plus five distinct corner-case types (`empty`, `auth`, `failure`, `network`, `repeat`).

Not applicable: `invalid` (analyze's only user inputs on the detail page are button clicks; there is no free-text or URL field on this surface to reject malformed input from). `boundary` (the only caps in this component, `AUTO_ANALYZE_CAP` and `OUTLIER_IDEA_THRESHOLD`, gate the sidecar's automatic passes, not any control the user drives from the UI, so there is no UI edge to sit at).
