## Behavior notes

- Analysis is authored by a connected agent: it calls `crowsnest_video` for caption, metrics, transcript text and any existing analysis, then `crowsnest_save_analysis`. The user's part is reading the result on the video detail page (reload to see a new one). With no analysis both tabs read "No analysis yet" with no button and no key alert.
- Generate idea is in the action row of an analyzed video. The first press adds an idea ("Idea added to the inbox"), a second updates an untouched inbox idea ("Idea updated", also shown when a shortlisted or scripted idea is left as it was). The user stays on the page.
- Neither feature has autosave or history. The idea is built from the analysis, persona and outlier score at request time.

## analyze: test cases

Result markers: 🟢 pass, 🔴 bug, 🟡 blocked (missing dependency named in the cell). Rows still reading "not run" were not driven in QA round 1.

P0 slice 2a retired the in-app Analyze/Re-analyze button and the internal-model path behind it (`getOrCreateAnalysis`, `analyzeVideoAction`, `reanalyzeVideoAction`, `auto-analyze.ts`). Analysis is now authored only by an external agent through the `crowsnest_save_analysis` and `crowsnest_video` MCP tools; every ANALYZE-* row below that exercised the retired button, its gate faces, or its key-dependent states is retired along with it. Rows ANALYZE-14 and ANALYZE-15, about how an existing analysis renders, and the IDEA-* rows, about Generate idea, are unaffected and unchanged.

How to run these: start the dev server and open `http://localhost:3001` (never `127.0.0.1`), on a database with at least one tracked channel that has finished a sync. Seed a mix: a video with no analysis and one with an analysis already saved (through `crowsnest_save_analysis` or directly in `video_analyses`), and for the idea rows, the LLM proxy up and a key, or stopped/unset for the failure rows. "A second tab" shares the session; it is not a second browser. The route and action lens runs offline with `vitest` against a temporary SQLite database, no external service needed, covering `analyze.ts` and `ideas.ts`; every listed test already exists in the matching `*.test.ts` file. Browse-e2e cases are driven with the `browse` skill against the running dev server, per `references/browse-e2e-qa.md`. The offline rows run against the seeded fixture database with no external service; the live rows need a reachable Claude proxy and a key (Generate idea only, analysis itself needs no key anywhere).
