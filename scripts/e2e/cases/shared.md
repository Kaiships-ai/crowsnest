# Shared cases

Hand verification for crowsnest's shared, cross-cutting behavior: the data model, the
interaction model, navigation and the shell, background jobs, external services, status
and failure surfaces, and persistence. These are the claims that many components depend
on rather than any single one, which is why they live here instead of in a component's
own cases file.

## How to run a pass

Bring up the dev server at `http://localhost:3001` (not `127.0.0.1`, which can silently
block server actions) against a seeded database with at least one tracked channel that is
not the own channel, one analyzed video, one saved post, and at least one planned post
(a scheduled one and one dated in the past). Several rows need a backing service toggled
from its default:

- Graph token invalid: clear or invalidate the token.
- Sidecar off: stop the Instagram sync sidecar.
- Whisper only: whisper.cpp installed, no Groq key.
- A soft removed video: set a video's `deletedAt` to simulate a sync removal.
- A second tab on the same record: shares the session, not a second browser.

Restore each service between sections so a leftover down state does not bleed into a row
that needs it up. A few rows read the database directly (a `createRuns` row, a
`plannedPosts` state) because the claim is a stored value, not a screen; the Needs column
says so. Work P1 first, then P2, then P3. Record `pass`, `fail`, or `blocked` in the Result
column; the placeholder below is `not run`.

Verified against commit `4f26fb9`. The parenthetical citations after each claim (for
example `([data-model.md#planned-post](../../../documents/architecture/data.md))`) link to the section of
the shared document the claim was read from. Every one of those documents now lives beside
this one under `documents/architect/shared/`, so a citation is a plain same-directory link.
