### Behavior notes

The MCP has no screen. Its users are MCP clients calling `/api/mcp`, so the cases below drive handlers and an in-memory transport, not a browser.

- Every tool returns through `result()` (JSON text plus `structuredContent`, always equal) or `errorResult()` (`isError`, never a throw). An unknown id or a missing own channel is an error result.
- `crowsnest_feed` pages in SQL and returns `{ total, count, items }`. `crowsnest_scripts` and `crowsnest_ideas` slice in memory over the full list.
- `crowsnest_video` and `crowsnest_brief` return `media` and `thumbnail` as `{ path, byteSize, durationSec }` read off the stored row. A null id gives a null block and an unresolvable path gives a null `path`.
- `crowsnest_metrics` returns `{ current, previous, posts }`, the prior window being the same length at offset `windowDays`.
- The remix chain is keyless. `hooks`, `outline` (with no `outline` argument), and `variants` return `{ system, user, context }`. `outline` with an argument persists it, and the script prompt needs that saved outline. `crowsnest_remix_finish` is idempotent.
- `crowsnest_sync_selected` refuses an empty `channelIds` with `NO_CHANNELS`. `crowsnest_sync_status` returns null progress for an unknown job. `crowsnest_sync_cancel` is cooperative. `crowsnest_ig_status` never errors.
- `crowsnest_save_analysis` writes nothing for an unknown video or invalid fields, stamps `source = "mcp"`, and updates one row per video.
- `crowsnest_transcribe` is cache-first (`cached: true` on repeat) and returns an error result for a photo, an unreachable sidecar, or no provider.
- Every request needs a live bearer token; a missing, unknown, or revoked one gets 401 before any tool runs. Reach is also set by the bind.

## mcp: test cases

Result markers: 🟢 pass, 🔴 fail, 🟡 blocked or not directly covered by a test, blank or `not run` before a case's test gate.

How to run these: the mcp component is covered by offline vitest suites, `src/server/mcp/mcp-server.test.ts`, `src/server/mcp/mcp-roundtrip.test.ts`, `src/server/mcp/mcp-sync-selected-success.test.ts`, `src/server/mcp/mcp-ig-status.test.ts`, `src/server/mcp/mcp-remix-keyless.test.ts`, and `src/server/mcp/gates.test.ts`, with the backing query and service functions covered in `src/server/queries/research.test.ts`, `src/server/queries/own-channel.test.ts`, `src/server/services/analyze.test.ts`, and `src/server/db/video-analyses-source.test.ts`. From the repo root, `pnpm test` runs the full suite, or `npx vitest run src/server/mcp/` for the mcp files. The cases that touch data migrate a temporary SQLite database in-process (`@/server/db/test-migrate`) and seed rows directly, so no network, no sidecar, and no model key are needed. The component has no screen of its own: it is called by an MCP client over `/api/mcp`, not driven through the crowsnest UI, so the behavior and browse-e2e lenses have nothing in the app to click and are noted N/A with their reason.

## 3. browse-e2e

Not applicable: mcp has no UI; its clients are programs, not people at a screen. Its behavior is
covered by the route-and-action lens (the tool handlers in `mcp-server.test.ts`, reaching each
handler through `_registeredTools`) and the live MCP round-trip (`mcp-roundtrip.test.ts`, driving a
real `Client` over `InMemoryTransport`). There is no browser surface for the coverage mandate to
apply to: a `browse` journey drives a headless browser and cannot make an MCP `tools/call`, and no
crowsnest page invokes these tools, so there is no route to `Arrive` on, no `data-testid` to target,
and no journey to script under `scripts/e2e/`. The mandate's happy-path-per-built-feature floor and
its five-distinct-corner-case floor are recorded here as not applicable for this component, the same
latitude the taxonomy grants a component with no threat surface.

Every corner-case type the taxonomy names is exercised at the handler level instead, where it is
observable, rather than through a browser that has nothing to click:

- `empty` and `boundary`: `crowsnest_scripts`/`crowsnest_ideas` slice by `limit`/`offset` with
  `total`/`count` reflecting the page (ACTION-05, ACTION-06).
- `invalid`: `crowsnest_sync_selected` rejects an empty `channelIds` array with code `NO_CHANNELS`
  (ACTION-12); `crowsnest_save_analysis` rejects fields that fail `VideoAnalysisSchema` and writes no
  row (ACTION-17).
- `failure`/`network`: a handled failure (unknown id, an unknown job, a refused sync start, a down
  sidecar) crosses the boundary as an `isError` result, never a thrown exception, except
  `crowsnest_ig_status`, which reports "the sidecar is down" as a successful read rather than an
  error, exactly like `crowsnest_sync_status`'s null progress for an unknown job (ACTION-02,
  ACTION-13, ACTION-13a, ACTION-14, ACTION-15, ACTION-20, ACTION-22).
- `repeat`: a second `crowsnest_save_analysis` for the same video upserts the one `video_analyses`
  row in place rather than inserting a duplicate (ACTION-18); `crowsnest_remix_finish` is idempotent
  and reuses the one undated draft planned post.

The web app's dashboard that BEH-02 once compared against is deleted, so there is no browser-driven cross-lens check left.

No `data-testid` gap is filed to the GitHub backlog (label `backlog`): with no journey to
script, there is no element to tag, so there is nothing for a later QA round to be blocked on.
