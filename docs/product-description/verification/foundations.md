# Verification: foundations

How to run this file: bring up the surface per the [protocol](README.md#how-to-run-a-pass) (dev server, `http://localhost:3001`, commit `4f26fb9`). For foundations start from a seeded database with at least one tracked channel that is not the own channel, one analyzed video in the feed, one saved post, and at least one planned post (a scheduled one and, for the missed and published rows, one dated in the past). Several rows need a service toggled from its default: LLM proxy down (stop the local proxy or unset `LLM_BASE_URL`), sidecar off (stop the sidecar), Graph token invalid (clear the token), and a soft removed video (set a video's `deletedAt`). A few rows read the database directly (a `createRuns` row, a `plannedPosts` state) because the claim is a stored value, not a screen; those say so in Needs. Most claims here are established facts other documents depend on, so a fail is more likely to be a wrong document than a product bug; say which when you file it.
